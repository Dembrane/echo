One tick, end to end

The order things happen in. Everything below is a stage of this.

A session is manual by default: nothing is scheduled, Refresh runs one tick, Rerun wipes the phrases, quotes and analysis (the saved runs stay) and runs one. Live is a choice with a duration (1, 8 or 24 hours): the two-minute chain until the expiry, then back to manual. Only the scheduled chain answers to the mode and the expiry; a read on request goes ahead in any mode. A tick that finds a conversation still owed its second pass, or an analysis view that failed last time, runs that even when no transcript changed. The second pass and the analysis both read the transcripts and neither reads the other, so they run together.

Two things protect the room from a long tick. The run lock stops a second tick from writing the same state; only the tick that took it can renew or release it. The heartbeat key tells the reconciler (which rescues ticks whose worker died) that this one is alive, however long its second pass or its pipeline takes, so a slow tick is never rescued as a dead one, and a dead one is still noticed within ninety seconds.

1

Gather and fingerprint

What the tick reads, and how it knows what changed.

ReadFromUsed for
id, participant name, created at, durationconversation, oldest firstthe legend, the timeline, the order of the deck
transcript, timestamp, created atconversation_chunk, by timestampjoined with line breaks into one transcript per conversation; the whole of it is fingerprinted and quoted against, and the model reads its most recent 150,000 characters
the host's voice notepopcorn settingsappended to the extractor's message; a change of voice re-reads every conversation

Each conversation gets a fingerprint of its whole transcript and the voice note, so new speech and a change of voice re-read it. A new prompt version does not: it applies to conversations read after it ships, and to a rerun. A conversation is re-read when its fingerprint moved or its last read never finished. On a runaway recording the model reads the most recent window; the host's bundle says how much lies before it (coverage). A conversation that vanished (deleted, or its chunks gone) leaves the deck with the tick; when the last one vanishes, the slides and the quotes go with it.

2

The fast pass

One call per changed conversation, sixteen in parallel, thinking off. Latency is the point: the first phrase is on the wall in one to four seconds.

The shaper code

CheckRuleWhat happens
lengthat most 90 characters and 13 wordsthe phrase is dropped
quotation marksnone inside the phrasedropped
terminal punctuationa trailing . ! ; : is stripped; a trailing ? is stripped and remembered as question: truethe deck draws the question mark back, only then
duplicatesthe same words twice, normalisedthe second is dropped
idsa hash of the phrase texta re-read that returns the same phrase keeps its id, so the stage does not pop it twice

The gates code

CheckRuleWhat happens
a namea capitalised word the transcript introduces someone by ("I'm Priya", "Thanks, Tom", "what Aisha was saying"), in any Latin scriptheld back, never on screen; kept on the state for the host
known textsix consecutive words shared with a phrase from another conversation or with slide text the room was shown (never with quotes, which are the room's own words)held back: the tool was quoting itself
twinstwo phrases with matching polarity sharing half their content words (Jaccard 0.5)the first stays, the other is held back

Grounding is code, not a model call: a phrase found verbatim in the transcript is flagged as such, and every phrase gets its closest passage (rarity-weighted word overlap) for the host's "why this phrase". The room never sees the passage.

3

The second pass

Only after every fast extractor has written. Two calls per phrase owed, asked at once, eight in flight, thinking on. Applied in one write per conversation, so a phrase is never half-updated on the wall.

A re-read keeps a phrase's reviewed wording, kind and quote while its passage remains in the transcript. A question rewrite keeps its corrected words; the display gates and verbatim check run on those words. Rejections apply only to the input checked: new speech or a changed voice note triggers reconsideration. The model's reasons, the objection's target and any scrubbed names stay under review on the state. The bundle never emits review.

4

One quote registry

Every quote of the session in one list at the top of the state, so a quote id the deck holds stays valid across ticks.

RuleWhat it means
seededeach tick starts from the registry it inherited; a seeded quote whose conversation is gone is dropped with it
verbatim onlya quote that is not in any transcript word for word is refused; one the model credited to the wrong table is credited to the table that said it, and the run's log line counts those
one per tablethe same words said at two tables are two quotes, one per conversation, so the modal names the right table
no speakera context line naming a person, a pronoun, an organisation, or a name from the introductions is dropped: the transcripts carry no speakers, so a context that assigns one is a guess
prunedafter the analysis, only quotes something on the deck cites are kept

Stakeholders

One call over the whole session (a 600,000-character budget, shared so short transcripts keep every character and the long ones split what is left), thinking on, five-minute timeout, behind two checks with one retry.

The second answer is taken as it is; what still fails is written into the run's log line. The rung (voiced, named, inferred) and the weights are the model's, not checked by code.

6

Tensions

A pipeline of single judgements, every call one question, run beside the stakeholders call. Two to six minutes on eight tables, depending on the model.

The known-text gate is not applied to tensions on the platform. In the lab it caught the theme cards read aloud into the room; here the only "shown text" would be the previous tick's own tensions, and a tension that persists across ticks must not trip it. The handed list in the verify call does that gate's job.
7

What leaves the state

The deck polls one bundle; the server assembles it from the state each time, in two variants.

The host's bundle

  • labels are the names typed on the phones
  • an unrooted phrase carries its closest passage, as a reading aid
  • quotes carry a link into the dashboard
  • host controls: hide a tab, the QR code

The room's bundle

  • labels are "Conversation 1, 2, 3" unless the host sets public_labels to names
  • no passages, no links, no host controls
  • the same bundle the host's fullscreen presenting mode asks for
  • no review field ever, in either variant
FileCarries
session.jsontitle, date, the transcripts with label, start time and duration (the timeline), the QR when on
popcorn/<id>.jsonper phrase: id, phrase, kind, question, qualifiers, quoteId, and verbatim when the phrase itself is in the transcript word for word (no weight: one size on the wall); validated is true when the second pass finished for the transcript as it stands; held_back counts the phrases the pass took off the deck; the host's copy carries coverage when the model read a window
quotes.jsonid, transcript, text, and a context only when it assigns no speaker
tensions.jsonpoles, knot, question, quote ids
stakeholders.jsongroups with rung and weights, relations with aspects, quote ids

The deck keeps polling a conversation's file until it is validated, and applies a validated file again when its revision moves, which happens when the transcript grows and the conversation is re-read.

Which model, and when it thinks

One group for every popcorn call.

CallPromptThinkingOutput cap
fast passpopcorn-v1.7off2,000 tokens
evidence, kind, question rewritepopcorn-validate, popcorn-kind, popcorn-questionon8,000
stakeholdersstakeholders-v0.9on32,000
handed, positions, collisions, verify, writethe five pipeline promptson32,000
dedupean inline instructionoff32,000

Every call goes through the platform's fast multimodal group, the same deployment as everything else that reads transcripts (gemini-3.7-flash in production), and every call is bounded: 60 s for the fast pass, 120 s for the second pass, 240 to 300 s for the analysis calls. The prompts are byte-for-byte the lab's, kept as immutable snapshots; a new version is a new file.
